# 未占用IP查找

Windows 免安装图形工具。输入 IPv4 网段、掩码和候选数量，查找连续两次 ICMP ping 未回应的地址，并将其标记为**待确认**。

## 使用

1. 运行 `dist\未占用IP查找.exe`。
2. 输入网段 IP、子网掩码，选择“按数量查找”或“全量扫描”。按数量查找时再输入候选数量；网关、起始 IP 可留空。
3. 点击“开始查找”。可停止扫描、复制选中地址或复制全部候选地址。

全量扫描会检查网段内所有可扫描主机地址，并显示已检查／可扫描、已回应、疑似空闲（待确认）、无法判断和耗时。结果区可切换查看三类 IP 明细。网段地址、广播地址和填写的网关不计入可扫描地址。每类结果最多展示前 1000 个地址，“复制全部”仍包含该分类的全部地址。中途停止时只统计已检查部分，不显示为网段最终结果。

当前默认版本采用 **WinUI 3 原生控件**和 Windows App SDK 2.5.1，跟随系统浅色或深色主题，并在系统支持时使用 Mica 窗口材质。宽窗口并排显示设置与结果，窄窗口上下排列并可滚动；找到首个候选时会滚动到结果区。剪贴板暂时被占用时，程序最多重试三次，失败后显示提示。

起始 IP 留空时，从首个可用主机地址开始；填写后从该地址扫描到网段末尾，再从开头继续。网段地址、广播地址及填写的网关会跳过。网关未回应时，程序提示并继续扫描。输入保存在当前 Windows 用户的 `%LOCALAPPDATA%\PingCandidateFinder\settings.json`。

**注意：**“疑似空闲（待确认）”只表示连续两次 ping 未回应。防火墙、休眠设备、地址预留等也可能造成未回应，不能据此认定地址一定空闲。路由不可达及其他网络错误会计入“无法判断”，不会列为候选。

## 开发与构建

开发机需要 Windows 和 .NET 8 SDK；默认从官方 NuGet 源恢复锁定版本的依赖。在 Windows PowerShell 中运行：

```powershell
.\build.ps1
.\test-winui.ps1
```

生成的 `dist\未占用IP查找.exe` 是面向 Windows 10 版本 2004（19041）及更新版本的 x64 单文件、自包含 WinUI 3 程序；目标电脑无需另装 .NET 运行时。首次启动会把依赖解包到临时目录，文件体积较大。测试覆盖扫描顺序、地址回绕、扫描取消、本机 ICMP 回环，以及“复制全部→复制选中”时剪贴板被占用的回归场景。

依赖版本记录在 `winui\packages.lock.json`。`build.ps1` 默认启用 NuGet 漏洞审计；若本机无法连接官方漏洞公告源，会出现 `NU1900`，此时不能视为审计通过。GitHub Actions 在 Windows 上运行测试和构建，并把漏洞公告不可用或发现已知漏洞视为失败。仅当本机的 NuGet HTTPS 连接确实不可用时，可用安装了 Python 的开发机运行 `build-local-proxy.ps1`；该应急脚本会跳过漏洞审计，因此产物仍须经过 CI 检查。

程序图标的 PNG 源文件和多尺寸 ICO 文件位于 `winui\Assets`；构建时会将 ICO 嵌入 exe，并用于窗口标题栏。

原 Python/Tk 版本和 WPF 试验源码作为历史版本保留；默认构建和交付不使用它们。`/23` 找 5 个候选的 30 秒目标和 `/16` 全扫 5 分钟目标仍需在实际网络环境验证。
